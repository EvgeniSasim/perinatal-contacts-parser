# Handoff: Analyst → Coder (v0.2)

## Что установлено

1. **Блокер итерации:** 382 из 482 записей (79%) без сайта. Без домена ФИО и email недостижимы → `site_discovery` первый по приоритету.
2. Страницы руководства существуют на ~70% доступных доменов; типовые пути: `/kontakty/`, `/administratsiya`, `/glavnyy-vrach`, `/management.php`, `/leadership`, `/o-bolnitse/`.
3. **Окно символов не работает.** Привязка ФИО↔должность обязана быть по структурному блоку (`tr`, `li`, `td`, карточка, абзац), иначе заместители попадают в `chief`. Подтверждено на 18 живых сайтах.
4. ФИО часто разорвано `<br>` внутри ячейки → перед матчингом схлопывать пробелы в блоке.
5. Есть ловушки: «Приемная главного врача … Секретари Иванова И.И.» → нужен фильтр антипаттернов и предпочтение самого «глубокого» (мелкого) блока.

## Требования к реализации

### site_discovery (порядок стратегий)

1. `existing` — `website` уже в БД.
2. `osm` — Nominatim по «название + город», взять `extratags.website`.
3. `catalog` — сопоставление с записями OrgPage/MedAdvisor по `name_norm + city`.
4. `registry` — ручной ввод из YAML / Admin UI.
5. `2gis` / `yandex` — если заданы ключи.

Валидация домена: ответ 200 (допускается `http://`), в тексте главной встречается город или ключевое слово названия. Иначе `crawl_attempts.status = not_found`.

### page_finder

- ≤2 уровня в глубину, ≤12 страниц на домен, ≤1 rps, таймаут 20 с, 2 ретрая.
- Классифицировать страницу: `leadership` / `contacts` / `departments` / `other` — от этого зависит `confidence`.
- Только тот же домен (никаких внешних переходов).

### person_extractor

- Итерировать по структурным блокам, брать **самый глубокий** блок, где есть и роль, и ФИО.
- Роль определять по `docs/roles-dictionary.md`; `deputy` проверять раньше `chief`.
- Применять антипаттерны (бухгалтер, медсестра, внештатный, секретарь, «наши специалисты»).
- `pathology_head` — только если в блоке есть и `заведующ`, и `патолог`; сохранять `department`.
- `confidence`: `high` на странице `leadership`, `medium` на `contacts`/`departments`, `low` без роли в блоке.
- `low` **не** попадает в `institutions.chief_physician` / `pathology_head`.

### Идемпотентность

- Upsert персон по `(institution_id, full_name_norm, role)`.
- Персона с `verified_manually = true` **не** перезаписывается автообогащением.
- `crawl_attempts` пишется на каждый шаг — для диагностики и чтобы не долбить мёртвые домены повторно.

## Do not

- Не парсить HTML `2gis.ru` / `yandex.ru/maps` — только API.
- Не выходить за allowlist, не принимать произвольный URL от клиента.
- Не включать живую рассылку без `dry_run=false` **и** `ALLOW_LIVE_MAIL=1`.
- Не ломать текущий контракт `/api/v1/institutions` (только добавление полей).

## Прогноз

Цель chief ≥60% реалистична как верхняя граница (оценка 45–60%). При недоборе фиксировать факт и причины, не подгонять.
