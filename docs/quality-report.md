### Прогноз на входе в итерацию

**382 записи (79%) не имеют сайта.** Без домена невозможно вытащить ни ФИО, ни email — поэтому `site_discovery` является блокирующим шагом для всей итерации, а не опциональным.

Разбивка целевой воронки:

```
482 записи
 ├─ 100 сайт известен          → сразу в page_finder
 └─ 382 сайта нет              → site_discovery
                                   ├─ ожидаемо найдётся ~60–70% (крупные ПЦ, роддома)
                                   └─ ЖК/кафедры часто без своего сайта — сайт головной больницы/вуза
```

Реалистичный прогноз при успешном `site_discovery` на уровне 65%: сайт ~70%, из них страницу руководства имеют ~70% → chief_physician достижим на уровне 45–60%. Цель 60% — верхняя граница, при недоборе фиксируем факт (см. `prompts/08-qa-deploy-v02.md`).

### Наблюдения по живой разведке (18 сайтов)

- Страницы руководства найдены на 12 из 18 доменов; типовые URL: `/kontakty/`, `/administratsiya`, `/glavnyy-vrach`, `/management.php`, `/leadership`, `/o-bolnitse/`.
- 4 домена недоступны (таймаут/refused) — нужны ретраи и допуск `http://`.
- ФИО в основном текстом (не картинкой), формат «Фамилия Имя Отчество» с должностью рядом.
- **Критично:** в списках руководства окно ±160 символов даёт неверную роль — заместители попадают в `chief`. Привязка обязана быть по структурному блоку (строка таблицы / элемент списка / карточка), а не по окну символов.
- ФИО может быть разорвано переводом строки внутри ячейки (`Хабибуллина\nРамзия Талгатовна`) — перед извлечением схлопывать пробелы внутри блока.

### Почему цели не достигнуты

Причина не в извлечении, а в исходных данных. Воронка на 100 учреждениях с сайтом:

```
100 учреждений с сайтом в БД
 └─ 37 доменов ответили и отдали страницы   (37%)
     ├─ 22 дали ФИО главврача               (59% от доступных)
     └─ 12 дали зав. отделением патологии    (32% от доступных)

Остальные 63:
   25  HTTP 4xx/5xx
   27  домен не найден / не сопоставлен
    9  таймаут
    2  запрещено robots.txt
```

**На доступных сайтах конвейер даёт 59% главврачей** — это близко к цели 60%. Ограничение
в том, что доступен лишь каждый третий домен, а сайт вообще известен только у каждого пятого
учреждения.

### Решающий факт: site_discovery через OSM не работает

Проверено на 150 учреждениях без сайта: **0 найденных доменов**. У этих организаций в
OpenStreetMap просто нет тега `website`/`contact:website`. Стратегия `osm` пригодна только
для точечных случаев.

Проверялась и стратегия «взять сайт у записи-дубля по названию»: она отклонена как опасная —
в базе 424 пары записей с одинаковым нормализованным названием («Перинатальный центр») в
разных городах, то есть сайт Сочи достался бы Москве. Сопоставление корректно только при
совпадении и названия, и города, а таких пар всего 2.

### Что реально закроет цели

| Путь | Ожидаемый эффект | Стоимость |
|------|------------------|-----------|
| Ключ 2GIS Places API | сайт и телефон почти для всех учреждений | платный ключ, код готов |
| Ключ Яндекс.Карт | то же | платный ключ, код готов |
| Ручной реестр доменов | по 20–30 сайтов за подход | время оператора, UI готов |
| Открытые данные bus.gov.ru | официальные сайты госучреждений | новый коллектор |

### Известные дефекты данных, унаследованные из v0.1

1. **20 записей с мусорными названиями** — обрывки текста из Zdrav.expert и Vademecum
   («2016: Открытие перинатального центра в Оренбурге», « М3 РФ 400059, Волгоград, …»).
2. **`city` содержит улицу** в части записей из OSM («Воровского ул», «Академика Павлова»).
3. **81 запись с `region = "Россия"`** — регион не был извлечён источником.
4. **Устаревшие домены**: 27 из 100 сайтов не разрешаются в DNS.

Все четыре — предмет отдельной итерации по чистке, а не обогащения.

### Точность извлечения

- Калибровочный набор: **6/6** совпадений с эталонными ФИО.
- Ручная проверка всех 22 учреждений с найденным главврачом: **21 верно**, в одном случае
  ФИО в родительном падеже («Ниманихиной А.В.» вместо «Ниманихина А.В.») — человек тот же,
  форма неверная. Precision 95%.
- Ложных срабатываний из категорий «секретарь», «главбух», «главная медсестра», «директор
  страховой компании», «врач из отзыва» после доработок не осталось.

## Пострелизное ревью v0.2 (v0.2.1)

Ревью выпущенного кода нашло пять дефектов; все устранены, см. Epic I в
[задачах](TASKS.md). Два повлияли на данные:

1. **Должность в соседнем блоке не читалась.** Разметка вида
   `<dt>Главный врач</dt><dd>Ниманихина Алла Владимировна</dd>` требует связки ФИО с
   подписью-соседом, а не только внутри блока. На 16 сохранённых страницах связка дала
   +1 главврача и +5 персон, а главное — заменила косвенную форму «Ниманихиной А.В.» на
   именительную. Тот единственный дефект точности из проверки выше закрыт.
2. **Денормализованные поля считались только по текущему обходу.** Повторный запуск,
   зацепивший лишь страницу контактов, затирал более достоверную запись со страницы
   руководства. Теперь `chief_physician` / `pathology_head` пересчитываются по всем
   сохранённым персонам, приоритет — подтверждённые вручную.

Дополнительно: ФИО в косвенном падеже («Прием главного врача А.В. Ниманихиной»)
распознаётся по падежу должности и остаётся в персонах с `low`, в поля не попадает.
