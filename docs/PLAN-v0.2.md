# План v0.2 — обогащение контактных персон

## Зачем эта итерация

MVP `v0.1.0` собрал каталог (482 учреждения, 127 регионов), но **именно те поля, которые нужны для рассылки, почти пустые**:

| Поле | Заполнено (из 482) | Цель v0.2 |
|------|--------------------|-----------|
| Адрес | 482 (100%) | сохранить |
| Телефон | 214 (44%) | ≥75% |
| **Email** | 12 (2%) | **≥60%** |
| **ФИО главного врача** | 1 (0%) | **≥60%** |
| **ФИО зав./зам. отделения патологии** | 0 (0%) | **≥25%** |
| Сайт учреждения | 100 (20%) | ≥70% |

Причина: справочники (OSM, MedAdvisor, OrgPage) дают адрес и телефон, но **не дают руководство**. ФИО живут только на официальных сайтах учреждений — на страницах «Руководство», «Администрация», «Контакты», «Отделения».

## Ключевая идея

Двухступенчатый конвейер обогащения:

```
институт без сайта ──▶ discover_site ──▶ найден домен
                                            │
                          ┌─────────────────┴─────────────────┐
                          ▼                                   ▼
                  find_pages (Руководство/       parse_persons (ФИО + должность)
                  Контакты/Отделения)                          │
                          │                                    ▼
                          └──────────▶ parse_contacts (email/tel) ──▶ DB
```

### Шаг 1. Поиск официального сайта (`site_discovery`)

Кандидаты домена в порядке приоритета:

1. `website` из справочников (OrgPage отдаёт домены).
2. Поиск по OSM `contact:website`.
3. Ссылка с bus.gov.ru / регионального минздрава (по названию + городу).
4. Ручной ввод в Admin UI.

Валидация: домен отвечает 200, в тексте главной есть название/город учреждения.

### Шаг 2. Обход разделов сайта (`page_finder`)

Ищем ссылки по якорям (regex, без строгих селекторов — вёрстка у всех разная):

| Цель | Паттерны в тексте/URL |
|------|----------------------|
| Руководство | `руководств`, `администрац`, `главный врач`, `upravlenie`, `rukovodstvo`, `administration` |
| Контакты | `контакт`, `contacts`, `svedeniya` |
| Отделения | `отделен`, `структур`, `подразделен`, `otdelenie`, `struktura` |
| Патология | `патолог`, `патология беременности`, `ОПБ` |

Ограничения: максимум 2 уровня в глубину, ≤12 страниц на домен, ≤1 rps на домен.

### Шаг 3. Извлечение персон (`person_extractor`)

Правила извлечения ФИО (русская морфология без ML):

- Полное ФИО: `Иванов Иван Иванович` — `[А-ЯЁ][а-яё]+\s[А-ЯЁ][а-яё]+(ович|евич|ич|овна|евна|ична)`
- Инициалы: `Иванов И.И.` / `И.И. Иванов`
- Должность рядом (±200 символов): `главный врач`, `и.о. главного врача`, `заместитель главного врача`, `заведующий отделением`, `начальник`
- Привязка к отделению патологии: должность + `патолог` в том же блоке (заголовок таблицы/карточки/абзаца)

Каждая персона получает `confidence`:

| Уровень | Условие |
|---------|---------|
| `high` | ФИО полное + должность в том же элементе + страница «Руководство» |
| `medium` | ФИО + должность в пределах блока |
| `low` | ФИО без явной должности рядом |

`low` **не пишем** в основные поля — только в `candidates` для ручной проверки.

## Изменения модели данных

Новые таблицы (без ломки текущего API):

### `institution_persons`

| Column | Type | Notes |
|--------|------|-------|
| id | UUID PK | |
| institution_id | FK → institutions | |
| full_name | VARCHAR(256) | как на сайте |
| role | VARCHAR(64) | `chief`, `deputy`, `pathology_head`, `other` |
| role_raw | VARCHAR(256) | оригинальная должность |
| department | VARCHAR(256) NULL | «Отделение патологии беременности» |
| email | VARCHAR(256) NULL | персональный, если указан |
| phone | VARCHAR(64) NULL | |
| confidence | VARCHAR(16) | `high`/`medium`/`low` |
| source_url | VARCHAR(2048) | конкретная страница |
| created_at / updated_at | TIMESTAMPTZ | |

### `crawl_attempts`

| Column | Type |
|--------|------|
| id | UUID |
| institution_id | FK |
| stage | `site_discovery`/`page_finder`/`person_extractor` |
| url | VARCHAR(2048) |
| status | `ok`/`not_found`/`blocked`/`error` |
| detail | TEXT |
| created_at | TIMESTAMPTZ |

Поля `institutions.chief_physician` и `pathology_head` остаются как **денормализованный кэш** лучшей персоны (`confidence >= medium`) — WP и Excel не меняются.

## Изменения API

Добавить (обратно совместимо):

```http
GET  /api/v1/institutions/{id}/persons
GET  /api/v1/institutions?has_chief=true&has_pathology_head=true&min_completeness=0.6
GET  /api/v1/meta/quality                 # % заполненности по полям и регионам
POST /api/v1/admin/jobs/enrich             # {"scope":"missing_chief","limit":100}
GET  /api/v1/admin/quality/report          # выгрузка проблемных записей
POST /api/v1/admin/institutions/{id}/verify  # подтвердить/отклонить персону
```

В `InstitutionOut` добавить:

```json
{
  "completeness": 0.72,
  "persons_count": 3,
  "has_chief": true,
  "has_pathology_head": false
}
```

## Изменения UI

### Admin UI

1. Колонка **«Полнота»** — прогресс-бар по 6 полям.
2. Фильтры **«нет email»**, **«нет главврача»**, **«нет патологии»** — рабочие очереди.
3. Карточка: блок **Персоны** — список с `confidence`, кнопки «подтвердить» / «отклонить» / «править».
4. Кнопка **«Обогатить»** на карточке (точечный запуск) и на фильтре (пакетно).
5. Экран **Качество данных**: заполненность по регионам, топ пустых.

### WordPress

- В карточку выводить главврача и контактное лицо, если есть.
- Новый атрибут shortcode: `[pnc_directory only_with_email="1"]` — для рассылочных страниц.

## Рассылка (доработка под задачу)

- Сегменты по `role`: рассылка **главврачам** отдельно от общих `info@`.
- Персональные подстановки: `{{full_name}}`, `{{institution}}`, `{{city}}`.
- Обязательный `unsubscribe` и лог отправок (кому/когда), чтобы не задваивать.
- Живая отправка только при `dry_run=false` **и** `ALLOW_LIVE_MAIL=1`.

## Мультиагентный пайплайн v0.2

Тот же состав, новые входы:

| # | Агент | Вход | Выход |
|---|-------|------|-------|
| 1 | Analyst | этот план + отчёт качества | `docs/handoffs/04-analyst-to-coder-v02.md`, реестр 30 сайтов для калибровки |
| 2 | Coder | handoff 04 | коллекторы `site_discovery`/`page_finder`/`person_extractor`, миграции, API, UI |
| 3 | Reviewer | diff | ревью: точность ФИО, robots/rate-limit, ложные срабатывания |
| 4 | QA & Deploy | ветка | ручная валидация 50 записей, метрики precision, релиз `v0.2.0` |

Промпты: `prompts/05-analyst-v02.md` … `prompts/08-qa-deploy-v02.md`.

## Критерии приёмки v0.2

- [ ] ФИО главного врача ≥60% записей, precision ≥90% на выборке 50 записей
- [ ] Отделение патологии ≥25% записей
- [ ] Email ≥60%
- [ ] Сайт учреждения ≥70%
- [ ] `GET /meta/quality` показывает метрики
- [ ] Admin UI: очередь «нет главврача» + подтверждение персоны
- [ ] Excel содержит колонки персон
- [ ] Ни одного домена не опрошено чаще 1 rps, robots соблюдён

## Риски именно этой итерации

| Риск | Митигация |
|------|-----------|
| Ложные ФИО (врачи из раздела «Специалисты» вместо главврача) | обязательна связка должность+ФИО, `low` не попадает в поля |
| ФИО в PDF/картинках (частая практика) | PDF — парсим (pypdf), картинки — помечаем «требует ручной ввод» |
| Часть сайтов на региональных поддоменах / без HTTPS | разрешить http, таймаут 20 с, 2 ретрая |
| Устаревшие ФИО (главврач сменился) | хранить `updated_at` персоны, ре-краулинг раз в 90 дней |
| Персональные данные | только публично опубликованные служебные контакты, никаких личных телефонов |
